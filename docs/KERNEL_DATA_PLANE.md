# Kernel Data Plane & Branchless MUX Specification

This document details the architectural layout and jitter-free optimization specifications of the eBPF/XDP kernel data plane (`target_kernel_xdp`) engineered to execute low-level packet acceleration and deterministic ingress filtration within the `homeostasis-ingress-firewall` framework.

---

## 1. Control-Data Plane Decoupling

The architecture leverages **eBPF/XDP (eXpress Data Path)** technology directly within the Network Interface Card (NIC) driver layer. This insulates line-rate packet traversal from the physical host-to-device communication bottlenecks and PCIe bus latencies inherently coupled with high-performance hardware accelerator (GPU/Triton) processing loops.

### 1) Autonomy of the Real-Time Execution Path (Hot Path)
- **Zero-GPU Intervention:** The ingress pipeline never duplicates, stalls, or routes live packet bytes to the GPU or user-space control plane (Rust daemon) for runtime evaluation. The native XDP program references its highly localized kernel map the exact cycle a packet enters the ring, independently enforcing absolute pass (`XDP_PASS`) or drop (`XDP_DROP`) actions.
- **Asynchronous Telemetry:** Rather than incurring transient memory replication costs by copying the packet payload, the driver extracts minimalist telemetric coordinates (RPS, PPS, Error Rate, Bandwidth Delta) strictly from fixed offsets within the packet header. These structures are pushed out asynchronously via a lock-free `BPF_MAP_TYPE_RINGBUF` framework at millisecond intervals on a fire-and-forget basis to the upper monitoring stacks.

## 2. Q16.16 Fixed-Point Arithmetic & eBPF Verifier Optimization

Floating-point hardware instruction sets are strictly forbidden within the Linux kernel runtime environment via eBPF. To circumvent this constraints infrastructure-wide, the framework implements integer-driven fixed-point mechanics to compute 3rd statistical moment (skewness) pre-damping entirely inside the kernel at bare-metal speeds.

### 1) Q16.16 Fixed-Point Arithmetic Rail
`target_kernel_xdp/xdp_ingress.c` deploys high-speed fixed-point math predicated on the `FIXED_ONE (65536)` scalar boundary to ensure deterministic performance.

```c
#define FIXED_SHIFT 16
#define FIXED_ONE (1 << FIXED_SHIFT)

// Fixed-point scaling implementation example
__u32 damped_signal = (variance_q16 * viscosity_alpha) >> FIXED_SHIFT;
```
- Before raw telemetric tensors are dispatched to the GPU accelerator plane, the kernel dampens initial traffic shockwaves utilizing solely integer multiplication and bit-shift registers, effectively reducing computational friction on the remote control plane.

> How do we prevent telemetry loss under BPF_MAP_TYPE_RINGBUF saturation scenarios?

Under worst-case line-rate bursts streaming 14.88 million packets per second, an overflow on the `bpf_ringbuf_reserve` allocation windows risks losing telemetric tracking payloads, which would blind the upper-level matrix validation loop.

To build an insulated fallback boundary, the data plane is engineered so that a ring-buffer reservation failure (`log == NULL`) triggers an atomic inheritance of the prior frame's gating mask (**Fallback Defend**), instead of a blind drop or loop exit. This guarantees that transient saturation across the telemetric channel never compromises the outer defensive line.

### 2) Securing Verifier Approval via `LOG_SIZE` Static Constants
The Linux kernel eBPF Verifier enforces aggressive static range checks; arbitrary or dynamically sized runtime boundaries can trick the static analysis compiler passes into rejecting the bytecode. To pass verification unconditionally, telemetric ring-buffer payload allocation footprints are locked into absolute literal macros.


```c
#define LOG_SIZE 32 // Locking down the absolute physical footprint of struct telemetry_payload

// Injecting static literal constants directly to guide the static analysis passes
struct telemetry_payload *log = bpf_ringbuf_reserve(&telemetry_queue, LOG_SIZE, 0);
```

## 3. Branchless Bitwise MUX Mechanics

Within highly parallelized line-rate environments, injecting conditional evaluation blocks such as `if (is_anomaly) return XDP_DROP;` triggers severe CPU Branch Misprediction rates, causing continuous execution pipeline stalls. To neutralize this overhead, `target_kernel_xdp/bitwise_mux.c` introduces branchless, pure mathematical register gating.

### 1) Single-Cycle Packet Evacuation via 2's Complement Masking
The system dynamically derives bitwise masks directly from the gating flag signals (`gate_mask`: absolute 0 or 1) generated by the acceleration loop and remote control planes.

```c
// Snippet from target_kernel_xdp/bitwise_mux.c
__s32 mask = -(__s32)gate_mask; // Maps 1 to 0xFFFFFFFF, maps 0 to 0x00000000

// Determining the ingress packet action solely via logical operations without conditional jumps
__u32 action = (XDP_DROP & mask) | (XDP_PASS & ~mask);
return action;
```

- When passed through the compiler backend, this block completely strips conditional jump assembly instructions (such as `JMP`, `JE`, `JNE`) from the execution sequence. Instead, it translates cleanly into deterministic logical primitives (`AND`, `NOT`, `OR`) or conditional move commands (`CMOV`). This forces raw packet drop execution within 1 to 2 hardware clock cycles at the instruction pipeline level.

## 4. 32-Byte Hardware Cache-Line Layout Alignment (ABI Alignment)

To drive serialization overhead between heterogeneous language platforms (`eBPF C -> Rust -> Python`) down to absolute zero, the binary layout of the kernel buffers matches the host memory structures down to the exact byte.

```c
struct telemetry_payload {
    __u32 src_ip;
    __u32 features[4]; // rps, pps, error_rate, bandwidth_delta
    __u64 packet_count;
    __u32 padding;
} __attribute__((aligned(32)));
```

- Locking the structural footprint to a total of 32 bytes via `__attribute__((aligned(32)))` guarantees perfect coordination with the L1/L2 cache-line stride boundaries of the underlying CPU architecture.
- This design allows the structure to map identically over the `#[repr(C, align(32))]` structure defined within `telemetry/ring_buffer_monitor.rs`. Data layers interface via raw virtual memory overlaps, executing a zero-copy interlock straight to the top-level algebraic validation loops without transient memory copies.
